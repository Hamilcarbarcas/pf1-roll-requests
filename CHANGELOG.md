## [Unreleased]

### Added
- **Embedded requests (API).** A live roll request can now be placed inside a chat card another module owns, without either module taking the other's card away from it. `game.pf1RollRequests.embed(message, { slot, ... })` creates the request state and `renderEmbed(message, { slot, into })` draws it into an element the host supplies — so the host places it from its own render hook once its container exists, with no hook-ordering dependency between the two modules and no retry loop. State lives under `flags["pf1-roll-requests"].embeds.<slot>` and `message.content` is never read or written, which is what the existing auto-save conversion cannot offer a host that redraws its card from flags on every render. A card can carry any number of embeds, each with its own DC, targets, results, and `onResult` stream. Rolls re-render through a plain flag write; a player's roll crosses the existing socket to the GM, still the only writer to the message. Supported by `getEmbed`, `updateEmbed`, `closeEmbed`, `listEmbeds`, and a `controls: false` option that strips the widget to its rows for sitting inside a host's own card. `pf1RollRequests.rollComplete` and `onResult` payloads gain a `slot` field, `null` for a whole-card request. See [api.md](api.md#embedded-requests).
- **DM Check mode.** A new check mode for quickly resolving a check across a group of NPCs. Select the NPC tokens on the canvas, pick a check, and the module auto-rolls for every selected NPC (dialog-free, GM-side) and posts one card listing each result. Each token rolls independently so unlinked duplicates of one actor each get their own line. Aid Another is disabled and the roll mode defaults to Private GM Roll while the mode is selected (your prior roll mode is restored when you switch back to another mode); you can still override it to reveal results to players.
- **Token Check mode.** A new check mode that posts the same per-target card a Selection Check does, but takes its targets from the tokens selected on the canvas instead of the Prompt Actors checklist — no list to tick, and no need for the actor to be a configured character or a player-owned NPC on the viewed scene. Any token type is eligible. Targets are keyed by token, so unlinked duplicates of one actor each get their own row and result, and each row is rollable by whoever owns that token (the GM can roll any of them). DC, roll mode and Aid Another behave exactly as they do for a Selection Check. Cards are tagged `[Token Check]`.
- **Quick Perception quick action.** Prompts a Perception check from the tokens selected on the canvas — Spot Checks without the actor picker. A popup asks for an optional DC and flavor text first (clicking OK on an empty form is a normal use). The card is public with totals hidden from players and no Aid Another; a DC drives the GM's pass/fail marks only, and never blocks anyone from rolling, since telling a player they cannot succeed would leak the difficulty of a check whose totals they aren't shown. Spot Checks is unchanged and still available for prompting actors who have no token on the scene.
- **`useSelectedTokens` and `promptOptions` for registered quick actions (API).** A module's quick action can now take the canvas selection as its actor list (entries keyed by token id and carrying `tokenUUID`), and/or open the same optional DC / flavor popup before running, receiving the values as `options` in its callback. See [api.md](api.md#registering-quick-actions).
- **Obscured NPC names on targeted cards.** When [pf1-token-randomizer](https://github.com/Hamilcarbarcas/pf1-token-randomizer) is active, NPC token names shown on targeted/DM-check cards are run through its obscured-name gate, so non-observing players see the obscured name while the GM and observers still see the real one. No effect when the module isn't installed.
- **Check-kind label in the card title.** Request cards now show a small tag after the title indicating the check mode — `[Single Check]`, `[Multi-Check]`, or `[Selected Check]`. Auto-generated saving-throw cards are left untagged.
- **Custom roll formulas (API).** A `dice` request's `key` accepts any valid roll formula — `2d6+2`, `2d4-2` — not just a bare die. Formulas are validated when the request is created, so a typo surfaces on the GM's call rather than on whichever player clicks the roll button.
- **Result tables (API).** A request can carry a `resultTable` that maps the roll's total onto a label, so a card rolling `2d4-2` reports *Banana* instead of *2*. Rows are thresholds — each covers from its `min` up to the next row's `min - 1` — so a table cannot leave a value unmapped, and row order doesn't matter. With `showTable` the whole table renders into the card: every outcome with its range, the rolled row highlighted, and the portrait of each actor who landed there, updating live as results arrive. `clampTable` optionally trims the open ends to what the formula can actually roll (off by default, so a table larger than its formula still shows in full). The roll itself is never hidden — expanding a result row shows the formula and dice as usual. Setting a table forces the DC to null and suppresses the highest/average aggregate line, neither of which is meaningful for a mapped result. See [api.md](api.md#custom-formulas-and-result-tables).
- **Selection instead of a roll (API).** A request carrying a `resultTable` can set `selectFromTable` to swap the roll for a choice: the card's die becomes a list button, clicking it opens a dropdown of the table's outcomes, and the pick is recorded exactly as a roll would be — same result row, same live `showTable` highlight and portrait, same `onResult` / `awaitResult` delivery. The entry carries `selectedIndex` and `selectedLabel` alongside a `total` the table still maps back to the label. Works in every check mode. A pick is final by default; `allowRepick` opts a request into letting choices be changed while the card is up — the button stays live, and clicking it again reopens the dropdown on the current pick and replaces it, limited to the slot that person already filled so nobody can overwrite anyone else's choice. `type` and `key` become optional, Aid Another and `clampTable` are forced off, and bulk rolling is unavailable — a selection is a person's choice, so there is nothing to fire on their behalf. See [api.md](api.md#choosing-instead-of-rolling).
- **Card description slot (API).** Requests take a `description` of raw, unescaped HTML, rendered near the top of the card and visible to every player — for dropping in a reference table or a rules reminder of your own. `game.pf1RollRequests.setDescription(message, html)` replaces it on an existing card and re-renders in place, so it can be swapped after a roll to highlight the result.
- **`game.pf1RollRequests.closeRequest()` (API).** Deletes one or more request cards that are no longer needed, taking messages or IDs singly or as an array. It unregisters each card's `onResult` stream first, so a consumer doesn't receive the terminal `"cancelled"` event for a request that actually completed, and removes a batch in a single broadcast so the cards vanish together rather than one at a time.
- **`game.pf1RollRequests.lockRequest()` (API).** Closes a card to further results without deleting it: the roll and selection buttons disappear, a lock appears beside the title, and a click that races the re-render is refused. The counterpart to `closeRequest` for cards worth keeping on screen — a re-pickable selection whose choices are now final, for instance. Like `closeRequest` it unregisters the `onResult` stream first, so a locked request never delivers a terminal `"cancelled"` event, and any unresolved `awaitResult` promise resolves `null`. It also closes every embedded request on the card, and accepts a card that carries only embeds. See [api.md](api.md#closing-without-deleting-lockrequest).
- **`excludeTargets` opt-out for auto-save requests.** A module or macro can set `flags["pf1-roll-requests"].excludeTargets` to a list of token uuids on an action's chat card, and those tokens are left off the generated roll-request rows even though they remain in `message.system.targets`. This keeps that field meaning "tokens this action was used against" — which other modules rely on — while letting a caller say a particular target shouldn't roll the check. The motivating case is a thrown splash weapon, where the token taking the direct hit is a real target of the action but only the creatures in the burst roll the Reflex save. See [api.md](api.md#excluding-targets-from-an-auto-save-request).

- **Replace All Target Lists (setting).** A new world setting extends the auto-request conversion to actions carrying no saving throw and no configured check, so a plain attack's target list becomes a roll-request list too — same rows, portraits, defenses dropdown, canvas hover and click, and **Select All**. There is nothing to roll on such a card, so it has no roll button, no **Roll All** / **Roll NPCs**, and no **Select Passed** / **Select Failed**, which partition a set of results that will never exist. Off by default; requires **Auto-Request Saving Throws**, and only replaces a target list PF1 actually drew.

### Documentation
- **`autoRoll`, `targetedActors`, and `mode: "targeted"`** are now documented in [api.md](api.md#creating-requests) and in `createRequest`'s JSDoc. All three already worked; only the reference was missing them.

### Changed
- **Flavor text no longer replaces the card title.** A card with flavor text used it as the title *and* printed it again on the flavor line below, so the same string appeared twice — and since a targeted card has no "Roll \<check\>" prompt of its own, a flavored one never said what was being rolled at all. The title now always names the check and the flavor line carries the prose. (A selection request with no check takes its name from the flavor, so there the two are one string and only the title shows it.) Cards posted before this change keep the header they were created with until their next roll rebuilds them.
- **Bulk roll on every targeted card.** The GM-only **Roll All** button was previously limited to auto-generated save cards and to API-created targeted cards whose roll mode was blind. It now appears on any targeted card that still accepts results — selection, token, DM and API-created alike — joined by **Roll NPCs** whenever there is more than one target. Both skip the roll dialog, which the per-row buttons do not, so a one-target card keeps **Roll All** and drops only **Roll NPCs**. `game.pf1RollRequests.bulkRollTargeted()` gains the matching `{ which: "npcs" }` option.
- **Defenses panel uses icons instead of written labels.** The expanded per-target dropdown now labels each defense with the same glyph PF1 uses in its own target boxes — shield for AC, pointing hand for touch, shoe-prints for flat-footed, and PF1's heart / arrow / brain for Fortitude / Reflex / Will. The two CMD stats are a glyph pair — a leading fist marking the family, then PF1's own shield or shoe-prints — since PF1 can reuse the AC shield for CMD only because it never draws both at once, and this panel draws both. Spell resistance keeps its written **SR** label, having no system glyph. Hovering any stat shows its full name. Each row of stats now sits centred in its own outlined box; the note groups below are unchanged.
- **The defenses dropdown's heading posts a defenses card.** Clicking **Defenses** in an expanded target's dropdown posts PF1's own defenses card to chat, whispered to you — the same card PF1's target boxes produce when their AC box is clicked. `displayDefenseCard` refuses without ownership, so the heading is only rendered as a link for actors the viewer owns, rather than offering a click that can only warn.
- **A sole target's dropdown opens by itself.** A targeted card rendering exactly one row expands it on arrival rather than making the reader click for the only thing on the card. Counted in rendered rows, so a player who can see one row of three gets the same treatment.
- **Hovering a target's portrait or name highlights its token.** Rows on targeted and auto-generated save cards now highlight the token on the canvas while the pointer is over the portrait or the name, matching PF1's own target boxes. Clicking the portrait still selects the token.
- **Cards show actor art rather than the token image.** Portraits on targeted cards, the sub-observer portrait grid, and result rows all draw from the actor's image, falling back to the token texture when the actor has none. A top-down token map reads poorly at portrait size. Cards posted before this change keep the image they were created with.
- **Quick action actor picker starts empty.** A quick action with `promptActors` now opens its actor list with nothing checked instead of everything, and adds **Select All** / **Select None** buttons below the list. Prompting a subset — the common case — no longer means unchecking most of the party first.
- **`createRequest` always returns the card.** It previously returned the created `ChatMessage` only in `multi` and `targeted` modes and `undefined` for a single-check without `awaitResult`, leaving no handle for reading flags or closing the card afterwards. It now returns the message in every mode, and `undefined` only when the request was actually rejected. `awaitResult: true` still returns its result Promise instead.
- **Aid counts toward the feasibility gate.** The natural-20 feasibility check now adds the aid already banked toward a check before deciding whether the primary roller can succeed, so an actor who couldn't reach the DC alone but can with aid is no longer blocked.
- **Untrained Knowledge at low DCs.** A Knowledge check of DC 10 or lower can now be attempted without ranks, matching the rules-as-written exception; other trained-only skills (and Knowledge above DC 10) still require ranks.
- **Allow un-passable checks.** A DC sub-option that lets actors roll even when they cannot reach the DC on a natural 20 (the default behaviour still blocks them). Also lifts the aid requirement, so anyone may aid such a check. Trained-only skills without ranks stay gated.
- **Ignore aid requirement.** An Aid Another sub-option that lets anyone attempt to aid even when they couldn't succeed on the check themselves (the default still requires an aider to be able to make the check).
- **Skill & ability check actions.** An item action's **Saving Throw → Type** dropdown now offers **Skill Check** and **Ability Check** in addition to Fortitude / Reflex / Will. Picking one reveals a skill/ability picker, a DC field (formula-capable, like a save DC), and an optional effect note. Using the action against targets produces the same embedded targeted roll-request card that saving throws do — including a standalone check button in the card footer mirroring PF1's native save button (rolls the check for your selected token). From a player's perspective the card is indistinguishable from a saving throw: same button, placement, and behaviour, with no Aid Another and every target always able to roll. A check is mutually exclusive with a save on the same action, and the config is stored on the item so it travels with the item. Honours the existing **Auto-Request Saving Throws** setting.

### Fixed
- **Rapid clicks no longer roll a request several times.** A card's "already rolled" checks read the message flags, which only catch up once a result is committed — so every click that landed while the first roll was still resolving (dialog open, dice rolling, or a player's result in transit to the GM) passed those checks and posted its own result, each overwriting the last. A roll button now holds the slot it is about to fill from the moment it is clicked until that result is visibly committed, greys itself out while it works, and refuses a second click with a single notification rather than a stack of them. The GM additionally discards any result arriving for a slot that already has one, which also covers two people clicking the same button at the same moment on different clients, and any result arriving for a card that has since been closed with `lockRequest`. Re-picking on an `allowRepick` selection request is unaffected.

## [1.2.0] - 2026-07-17

### Added
- **Monster Lore window.** A Knowledge-check helper, opened from the new **Monster Lore** Quick Action. Pick a creature type (auto-selects the relevant Knowledge skill), CR, and rarity — or drag/select a reference token to auto-fill CR and type — then fire a public multi-check whose DC is hidden from players. The card shows a live "Questions earned" tally that grows as party members pass.
- **Result aggregate on multi/selection cards.** A new **Multi-Check Result Aggregate** setting can show the running **highest** or **average** of the roll totals at the top of multi-check and selection-check cards, below the title/DC. It updates live as results come in and follows the same visibility as the individual totals. Default is off.

### Changed
- All user-facing text (settings, menus, dialogs, chat cards, Monster Lore window, defenses panel, notifications) is now localizable via `game.i18n` (English `lang/en.json` included).
- Reordered the module settings and adjusted several defaults for a clearer configuration flow.
- Reorganized the module's source into a `src/` directory (`src/module`, `src/templates`, `src/styles`); the packaged release layout and manifest paths were updated to match.

## [1.1.0] - 2026-06-30

### Added
- **Targeted check mode.** Request a check for specific targets, with results matched per-target. Blind rolls are properly obfuscated so players only see what they should, and save-request embeds include defensive info for the relevant target.
- **Quick Actions.** New Quick Actions section in settings for one-click common requests, a built-in Spot Checks action, and API support for adding your own buttons.
- **NPC support.** Player-owned NPCs now appear in the actor selection list, with a new NPC blacklist to hide specific NPCs.
- **Saving throws.** Chat messages that include a saving throw can carry a roll request directly, and saving-throw requests can be attached to existing chat messages.
- **Aid Another.** Multi-check requests now support Aid Another.
- **Roll options & summaries.** New Roll Options configuration for finer control over what is displayed in the request window, plus a summary registry across all roll modes (also exposed through the API).
- Expanded public API: callbacks for multi-request flows, quick actions, summary registry, and roll options.

### Changed
- Reworked ownership detection for non-save requests.
- Project renamed to PF1e; module title updated and manifest link added.
- Aid Another rules updated to match Pathfinder core, with an optional house-rule setting granting +1 for every 5 points a check exceeds 10.
- Updated README.

### Fixed
- Automatic cleanup when a request card is deleted, so no orphaned multi-request state is left behind.
